# OpenMana

Modern, browser-first Magic: The Gathering client using Forge as the rules engine.

OpenMana succeeds Anvil, but is a clean web-first implementation rather than a Kotlin/Compose port.

## Goals

- Modern, beginner-friendly battlefield UX with an original OpenMana identity.
- Forge remains the single authority for Magic rules, card behaviour and AI.
- Target: Forge runs locally in the browser through WebAssembly; no Odin or Tailscale runtime dependency.
- Scryfall supplies card metadata and imagery, preferring German with English fallback.
- Arena-format decklists are imported and stored locally in IndexedDB (optionally kept in sync across devices through the player's ORYX account).
- One web codebase for browser/PWA and later an Android wrapper.
- Forge updates are isolated from the UI.

Start with [docs/BIBLE.md](docs/BIBLE.md).

## Status

Implementation has started; progress per queue prompt is tracked in [prompts/STATUS.md](prompts/STATUS.md).

- **Engine spike done (prompt 01):** pinned upstream Forge plus a small GPL patch queue runs as WebAssembly (GraalVM Web Image) in a Dedicated Worker and plays a complete Forge-AI game in Chrome; JVM, Node and Chrome produce the identical Forge game log. See [engine/README.md](engine/README.md) and [docs/implementation/01-engine-spike.md](docs/implementation/01-engine-spike.md).
- **Bridge spike done (prompt 02):** Forge's own human path (`PlayerControllerHuman` and its inputs) runs on a single thread through an Anvil-style bridge: numbered questions with withdrawal, card taps outside questions, mulligan, cost payment, targets, attacking, blocking, conceding. In the browser the worker waits for the player's input with `Atomics.wait` on a SharedArrayBuffer. Recorded human-vs-AI games replay identically on the JVM, in Node and in Chrome. See [docs/implementation/02-anvil-bridge.md](docs/implementation/02-anvil-bridge.md).
- **Protocol and transport done (prompt 03):** `engine/protocol` is the only UI↔engine contract: a versioned JSON Schema, TypeScript types and precompiled validators generated from it, and the SharedArrayBuffer input queue (bounded ring buffer, loud on overflow). The `EngineClient` (main thread) starts the Dedicated Worker, checks every engine message against the schema, tracks questions (stale and withdrawn answers are refused before they are sent), and reports ready/error/technical abort; the worker host checks protocol version and browser features before the engine is even downloaded. See [engine/protocol/README.md](engine/protocol/README.md) and [docs/implementation/03-worker-transport-protocol.md](docs/implementation/03-worker-transport-protocol.md).
- **Forge resources and card scripts done (prompt 04):** the engine embeds a deliberately chosen, inventoried set of Forge data from the pinned commit (every card and token script, editions, formats, lists, AI profiles, English and German messages; every other `res/` entry is left out with a reason, and a new one stops the build). The engine manifest records Forge SHA, patch hash, toolchain, resource inventory, sizes and SHA-256. A card probe turns every card of the database into a game card, checks every layout, every token, the newest sets and the effects that create cards by name — identically on the JVM, in Node and in Chrome. Network play (Netty, jupnp, Jetty) is kept out of the module and the build enforces it. Forge's texts can be German (`--language=de-DE`); cards load eagerly by default. See [docs/implementation/04-forge-resources-card-scripts.md](docs/implementation/04-forge-resources-card-scripts.md).
- **Differential tests done (prompt 05):** the same scripted games with fixed seeds run on the JVM and as WebAssembly in Node and Chrome and are compared by a structured, language-independent engine trace (every checkpoint and Forge event, no prose, no clock), entry by entry; any divergence fails and names its place in the game. Ten small game fixtures (`engine/fixtures`) cover mulligan, land/spell play, priority, cost payment, targeting, stack, combat, blocker assignment, zone movement, game end and a Commander game; German and English give the same trace. See [docs/implementation/05-engine-differential-tests.md](docs/implementation/05-engine-differential-tests.md).
- **Web app skeleton done (prompt 06):** the production web application lives at the repository root (React 19, Vite 8, TypeScript 7 strict, Tailwind 4 with shadcn/ui) with the surfaces Start, Decks, Play, Matches, Settings and Credits in German, a sidebar from tablet width and a tab bar on phones. OpenMana's own design system (dark night blue and gold, Cinzel headings, touch targets from 44 px) is defined in [docs/DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md). "Play" loads the real Forge engine through the `EngineClient` and shows its boot, readiness or abort; there is no invented game data. The build takes the engine only after checking size and SHA-256 of every file against its manifest and serves it content-addressed under `/engine/<id>/`. Every response carries COOP/COEP (dev server, preview, `vercel.json`); a web app manifest makes it installable; the temporary icon is Anvil's, unchanged. See [docs/implementation/06-web-pwa-skeleton.md](docs/implementation/06-web-pwa-skeleton.md).
- **Local data layer done (prompt 07):** decks, settings, recorded matches, Scryfall card data and cache bookkeeping have a versioned IndexedDB database (`openmana`, schema version 1) — never `localStorage`, no account, no cloud. Record shapes and the backup format are one JSON Schema (`src/storage/schema/`) with generated types and validators; migrations run in one transaction and upgrade older backups too; every write is all or nothing; failures (newer version, damaged structure, full storage, another tab, cleared site data) are shown with what can be done. Backups: a gzip-compressed JSON Lines file out, and back in after a complete check (merge or replace). Settings shows the data on the device, the browser's storage figures and a check of every record. See [docs/implementation/07-indexeddb-storage.md](docs/implementation/07-indexeddb-storage.md).
- **Scryfall card data done (prompt 08):** a card catalog built at build time from Scryfall's `all_cards` bulk data and Forge's card database (`npm run cards:build`, see [cards/README.md](cards/README.md)): one record per card with English faces, the printed German text, default printings (German picture where Scryfall has a real one, else English) and the Forge cards it is - 33 740 of Forge's 33 978 cards matched, the rest named with a reason. Served like the engine (size and SHA-256 checked, content-addressed under `/cards/<id>/`), installed into IndexedDB once per version from Settings (progress, stoppable), then names are found (German or English) and cards shown without asking Scryfall's API; pictures load straight from Scryfall's image server in CORS mode (required by COEP), never cropped. German first, English clearly marked where German is missing; double-faced cards, tokens and particular printings (fetched within Scryfall's rate limits and kept 30 days) handled. Settings show the catalog's Scryfall date and state; "Karte nachschlagen" looks cards up; Credits name Scryfall and Wizards of the Coast. Local database schema version 2. See [docs/implementation/08-scryfall-data.md](docs/implementation/08-scryfall-data.md).
- **Arena deck import done (prompt 09):** Decks → "Arena-Deck importieren" takes an MTG Arena deck list (pasted or as a text file): sections Deck, Sideboard, Commander, Companion and About/Name, counts, set and collector numbers, German or English names. Every line is resolved through the card catalog on the device to the card name Forge knows and Scryfall's Oracle id (faces, split cards, Universes Beyond names, Arena's rebalanced "A-" cards); only lines the catalog cannot decide that name a printing are asked of Scryfall (names in other languages, old German translations shared by two cards). The report shows every open line with its number - ambiguous names are the player's choice, cards Forge does not have are named, nothing is dropped silently - and saving is possible only when every line is clear and the deck has a name; the list is kept unchanged with the deck. No legality checks: Forge decides. The end-to-end test hands the imported decks to the real Forge engine. See [docs/implementation/09-arena-deck-import.md](docs/implementation/09-arena-deck-import.md).
- **Deck library done (prompt 10):** Decks lists every deck with its cover card, format, counts, commander and companion and how German its cards are; search by the deck's name or any card's name (German or English), filter by format, sort by name or date - all kept in the address. A deck's page shows its parts card by card (German where Scryfall has it, English marked, the printing the list named - its German version where there is one, fetched once), an overview and its language status; it can be played, renamed, duplicated, exported as an Arena list (with Forge's names, which imports again without a question, or the imported list unchanged; copied or saved as a text file), imported again (the saved list to change, earlier choices kept, replacing confirmed, same deck), given to the AI, deleted (confirmed). Play chooses the player's deck and the AI's - one of the player's decks of the same format or a random one, drawn anew for every game; both choices are kept. On phones the primary action stays in a bar above the tab bar. Decks now name their companion (local database schema version 3). See [docs/implementation/10-deck-library.md](docs/implementation/10-deck-library.md).
- **Game session done (prompt 11):** saved decks play a real game against Forge's AI in the browser. Opening Play with a deck prewarms the engine; "Partie starten" draws the AI's deck (random: anew for every game), hands both decks to Forge as data (the protocol's Deck with the names Forge knows, a seed the app draws) and leads to the game page (`/play/game`), which shows every state with a way on: waiting for the engine (its boot phases), Forge building the game, the running game (Forge's turn, step, life and zone sizes, the decision it waits for in its own German words), the result in one word, a refusal with Forge's report, a technical abort, a silent engine. Conceding and ending a game are confirmed; one engine at a time and a fresh one for every game; reloading asks first and ends the game. The end-to-end test plays Commander and Constructed games in Chrome, including a failed engine download and a deck Forge refuses. See [docs/implementation/11-game-session.md](docs/implementation/11-game-session.md).
- **AI profiles and settings done (prompt 12):** the player chooses Forge's AI profile once - "Standard", "Vorsichtig", "Waghalsig", "Experimentell" (Forge's Default, Cautious, Reckless, Experimental) or "Zufällig" - in Settings or on the play page, never as a step before a game. Each is described only by what it verifiably changes: the profile values and the Forge code reading them, plus 2 400 AI-against-AI games, found styles but no difficulty levels (none measurably stronger or weaker than Forge's default; see [docs/research/AI_PROFILES.md](docs/research/AI_PROFILES.md)). The engine reports the profiles it loaded and refuses any other (protocol 4); the build stops if Forge's profile files are not the verified ones. The card language (German where Scryfall has it, else English - or English) applies to every card the app shows and to the cards inside Forge's texts (new boot argument `--card-language`: Forge keeps speaking German). All animations stop when the device or the player asks for less motion. Settings name Forge's version and show a diagnostics report of every version to copy. See [docs/implementation/12-ai-profiles-settings.md](docs/implementation/12-ai-profiles-settings.md).
- **Game table foundation done (prompt 13):** a running game is a table built from Forge's full state that fills the screen (the app's navigation steps aside; the table's menu leads around the app, shows Forge's notices and concedes after asking) - on phones upright and turned, foldables, tablets and desktop. Fixed regions: the AI with its hand, its battlefield, stack and combat, your battlefield, you, Forge's decision, your hand; what does not fit scrolls inside its region (card rows sideways), never the page. Cards show their pictures from the card catalog in the player's card language (Forge's own words where the catalog cannot say which card it is), tapped cards are turned, their facts (power/toughness, damage, counters, attacking, blocking) stand below the picture, identical cards lie as one pile, auras and equipment lie with their card; what Forge hides stays a back (the AI's hand, face-down cards). The stack and combat are shown in Forge's words; Forge's decision is shown with the answers it offers. Checked with real recorded game states in the real table at six sizes. See [docs/implementation/13-battlefield-foundation.md](docs/implementation/13-battlefield-foundation.md).
- **ORYX cloud sync (outside the queue, 2026-09-25):** optional - connected to the player's ORYX account (the ORYX launcher's Supabase cloud), OpenMana keeps the decks, the marks of deleted decks and the settings shared between devices (not the card language or less motion) in sync across the player's devices. Two versions are merged, never chosen: per deck the newer change wins, a deleted deck stays deleted, and a download never replaces local data. Recorded matches, card data and the engine stay on the device. Active only at `openmana.vercel.app` (through the ORYX SDK, an unchanged copy); Settings → "ORYX-Cloud" connects and disconnects. Local database schema version 4 (deletion marks). See [docs/implementation/oryx-cloud-sync.md](docs/implementation/oryx-cloud-sync.md).
- **Cards, hand and safe interaction done (prompt 14):** every card the player may see is a control - on touch, with a mouse and by keyboard (one stop per row, arrow keys between cards). Looking is always safe: a card opens its card view (from below on phones, from the side in landscape) with the card large, Forge's words and facts and what Forge offers; nothing is sent. Playing or activating is the view's button, labelled with Forge's words ("Spiele ein Land") and protected against double taps; in the steps Forge lets the player take back (paying, attacking, blocking, the London mulligan, a selection) a tap acts at once and a long press or right click looks. Forge's state shows as a frame around the picture (usable: dashed gold, chosen: solid), never on it; nothing taps while Forge computes. Checked with real recorded game states in real Chrome at six sizes (clicks, double clicks, long presses, swipes, keys). See [docs/implementation/14-card-hand-interactions.md](docs/implementation/14-card-hand-interactions.md).
- **Forge's decisions done (prompt 15):** every kind of question Forge asks the player can be answered on the table, in the decision region right above the hand: Forge's two buttons (keep or mulligan, play or draw, OK or end turn, auto or cancel …), a selection (cards on the table are tapped there, cards the table does not show come as a row), choices from a list (modes, colours, cards, players - one or several, a long list with a search), yes or no, one of several options (and lists Forge only shows), a number or a text, an order, cards to the top or bottom of the library (scrying) and amounts to give out (combat damage). Nothing is answered for the player - Forge's suggestion is only the first draft, an answer that does not fit Forge's numbers is never sent and the button says why, sending buttons are armed a moment after they appear; a withdrawn question takes its controls with it, a refused answer shows as Forge's notice. The region grows only as far as a question needs, its buttons stay in reach, also on small phones and turned phones. The end-to-end test plays the real game in Chrome (keep, pass, play a land, pass) and answers every kind of question at six sizes. See [docs/implementation/15-forge-decisions.md](docs/implementation/15-forge-decisions.md).
- **Priority, stack and phases done (prompt 16):** the table's header shows Forge's step with a track of the turn's steps and whose turn it is; the player's priority says what it is about in words from Forge's state (whose turn, what lies on top of the stack) instead of Forge's status line, Forge's OK says what passing does ("Weiter", or "Verrechnen lassen" with something on the stack), Forge's "Zug beenden" asks first (it gives the rest of the turn away) and "Rückgängig" keeps Forge's words. Forge's own auto-pass stays in charge: a priority in which Forge finds nothing the player can do never reaches the table, and the app never passes by itself. The stack shows every item with its card, what it is, whose it is and its targets; its picture opens the card view. Protocol 5: stack items carry their card, Forge's priority buttons say what they do, a selection names only visible cards, and looking no longer changes Forge's objects. A new test game has the player answer the AI's spells. See [docs/implementation/16-priority-stack-phases.md](docs/implementation/16-priority-stack-phases.md).
- Not fully playable yet: players as targets (prompt 17) and the finer points of targeting and combat (prompts 17-19) follow. Anvil remains the working reference implementation until OpenMana reaches feature parity.

## Develop

```bash
npm ci                               # web app dependencies (repository root)
bash engine/scripts/build.sh         # build the Forge engine once (~6 min, see engine/README.md)
npm run cards:build                  # build the card catalog from Scryfall's bulk data (~45 s, see cards/README.md)
npm run dev                          # http://localhost:5173, cross-origin isolated
npm run check                        # typecheck, lint, unit tests, end-to-end test in Chrome with the real engine
npm run generate                     # after changing a schema (src/storage/schema, src/cards/scryfall): regenerate types and validators
```

`OPENMANA_ENGINE=omit npm run build` builds the UI without an engine, `OPENMANA_CARDS=omit` without card data (the app then says so); a normal build without a checked engine and card catalog fails. The end-to-end test loads real card pictures from Scryfall and needs internet access.
