# 23 — Beginner QoL

## Scope and authority

The table explains Forge's current state and questions without deciding a Magic rule or sending an answer. Existing legal-action/selection frames, attack refusals, block assignments, payment controls, tapped rotation, summoning-sickness hourglass, stack order, priority texts and irreversible-action confirmations remain authoritative presentations. Forge's own auto-pass remains the only auto-pass.

## Implemented aids

- **Contextual help:** the turn/phase area in the header is a labelled `GameHelpButton` with a help symbol, at least 44 px high. It opens a shadcn `Sheet` from below in portrait and from the right in landscape. Header/footer remain reachable while content scrolls. Escape/Close restores focus to the opener. The same help is available in snapshot replay, explicitly read-only.
- **Current decision:** `beginner-help.ts` resolves the current questions on every render using the existing blocking-question precedence. Guidance covers all nine question families and Forge's structured button purposes: priority, payment, attackers, blockers and mulligan. No card names, translated prose, state heuristics or suggestions determine optionality, legality or an action. Withdrawn questions leave no cached help behind; computing/concession/replay are identified honestly.
- **Required versus optional:** a concise label joins the existing decision heading. Select/choose use Forge's `min`; order uses the existing `orderRule` bounds; options use only explicit `cancellable`. Confirm says “Ja oder Nein”, never claims that a suggested yes is required or that an effect is optional. An optional zero-item selection still needs the player's explicit completion. Numeric boundaries are displayed literally, also when players and cards share a selection.
- **Phase and terminology:** static explanations for every protocol `Phase`; priority, stack, target/source, tapped, summoning sickness (Forge's existing explanation, with exceptions acknowledged), mulligan and mana/costs. These explain concepts, never predict a legal move or a future state. Unknown card facts and hidden identities remain unknown.
- **Already named targets:** exact `GameState.stack[].targets` IDs, with separate card/player sets. Visible table cards, stack cards and player seats get an explicit accessible target label and a double gold frame (player seats also show a crosshair) when no usable/selected frame takes precedence. The card viewer identifies the current relationship. A target mark never changes `cardUse`, `playerUse`, buttons, enabled states, tap guards or engine input. Missing/hidden cards do not gain a face/name; marks disappear with the next snapshot. Source/target relationships use no text parsing.
- **Technical failures:** structured abort reasons get German next steps in the existing engine and game error panels. Original technical messages/details remain intact. Reload advice states that a running game ends; no recovery is promised. Existing German input-rejection/deck-refusal explanations remain in place.

The help is intentionally on demand, without a new preference or database migration. It occupies no decision/battlefield space while closed. There are no engine, bridge, protocol, catalog, storage or cloud changes. All presentation uses existing shadcn components/theme tokens; the target frame reuses primary, with a distinct shape and words.

## Review findings

The first version added a fourth header icon; visual review at 360 px showed the turn/phase text squeezed too far. Help now uses the existing turn/phase area as its opener, with two-line phase text and accessible descriptions for the phase and turn owner. The expanded table still has eight regions. An explicit opener ref fixes focus restoration for the imperatively opened Sheet. Visual review also found that a visible “Ziel” word could consume the narrow creature caption at 360 px. The 360 px follow-up found that even the crosshair could truncate the narrow statistics line. Field captions therefore keep their original statistics space; the target word remains accessible and in the viewer/title. The old exact caption expectation now includes the new authoritative target label while preserving power/toughness/damage assertions. Browser selection-mark counts still verify the original usable/selected marks separately; an additional independent comparison checks target IDs against original recorded envelopes.

A review also caught the potential ambiguity of “any number” in selections that include players: help displays the actual numerical min/max instead of inferring the number of all candidates from card items. Static summoning-sickness terminology mentions that Forge handles exceptions such as haste. The target presentation includes cards on the stack, so a spell targeted by another spell can be emphasized without inventing a counterspell rule.
